# ISO 9660 只读文件系统

ISO 9660 是 OpenXJ380 的内建公共文件系统驱动，闭源 XJ380 使用同一份
Apache-2.0 实现。驱动在 FAT、ext4、NTFS 之后注册，通过已有 VFS 接口读取。

## 支持范围

- ISO 9660 Level 1、2 普通文件及目录，以及 Level 3 多区段文件。
- 单卷、2048 字节逻辑块。底层设备扇区与 ISO 逻辑块分别处理，复用块设备的
  字节读取接口；不要求底层设备也是 2048 字节扇区。
- 优先选择有效 Rock Ridge 树，其次是 Joliet，最后是基本 ISO 树。
  Joliet UCS-2 大端名称转 UTF-8；非法 UCS-2、超长名称和路径分隔符被拒绝。
- Rock Ridge/SUSP 支持 SP、ER、ES、CE、ST，恢复 NM 名称、PX 权限/属主/链接数/序列号、
  TF 时间戳、SL 符号链接，以及 CL/PL/RE 重定位的深层目录。支持跨区段的名称和链接组件。
  NM 名称保留原始字节和大小写，常见 UTF-8 镜像无需额外转换；查找精确匹配。
- PX 序列号恢复硬链接的 inode 标识；PN 保留特殊文件的设备号供 stat 查询。
  盘面设备、FIFO 和 socket 仅展示元数据，不创建可使用的内核端点。
- 基本 ISO 名称以 ASCII 小写显示，基本 ISO 卷按 ASCII 忽略大小写查找；Joliet 精确匹配。
- 基本 ISO/Joliet 普通文件名称隐藏数字版本后缀和末尾点。同名文件的不同版本显示最高版本；
  相同版本的重复目录项作为错误拒绝。关联文件不进入普通文件名称空间。
- 随机读取、EOF、64 位大小、多区段跨界读取，以及真实卷容量的 statfs。

所有挂载均只读；没有 PX 属性时普通文件权限为 0444，目录为 0555。
Rock Ridge 保留权限位，即使权限位包含写权限，文件系统仍只读。创建、写入、删除、
重命名、截断及元数据修改受到 VFS 的 EROFS 保护；底层解析器没有写回调。

UDF、音频 CD、原始 2352 字节扇区镜像、跨卷文件、交错文件、多会话选择、
写入/刻录、Rock Ridge SF 稀疏编码和 zisofs/ZF 压缩数据不在范围内。
SF/ZF 数据读取明确拒绝，避免将编码字节误当作文件内容。

## 挂载与生命周期

普通系统启动在根目录挂载后探测整盘 ISO，成功后挂载到 `/mnt/<设备名>`。
热插拔设备在分区扫描租约释放后进行同样探测。手动挂载接受 devfs 块设备或
普通 ISO 文件。VFS 来源可加 `iso9660:` 前缀；用户态使用已有的 mount(165)/umount2(166)
调用，filesystem 为 `iso9660`，来源为普通路径，挂载 flags 为 0 或 MS_RDONLY。
未实现的 bind/move/remount 等 flags 返回 EOPNOTSUPP。

两个工程均安装原生命令 `/apps/system/mountiso/mountiso.elf`，不需要 `/dev/loop`：

```sh
mkdir /mnt/disc
/apps/system/mountiso/mountiso.elf /users/alice/disc.iso /mnt/disc
/apps/system/mountiso/mountiso.elf -u /mnt/disc
```

用户态挂载/卸载要求 CS 与 NV 权限，且目标必须为 `/mnt` 的子目录；命令通过现有
权限请求接口申请缺失的权限。源文件继续使用原有读取权限，IME 受保护路径规则仍生效。
BusyBox mount 会自行尝试创建 loop 设备，应使用上述原生命令。
符号链接遵循现有 VFS 规则：相对目标以链接所在目录为基准，绝对目标从系统 `/` 开始。

挂载保留设备节点、注册代次和物理区间租约，拒绝重叠挂载。混合 ISO 的
整盘与内部 GPT/FAT 分区也遵循此限制。安装器模式不自动挂载 ISO，以保留
其源介质和安装目标的独占规则。此驱动不更改 UEFI/El Torito 启动流程。

普通文件来源按需读取，不将整个镜像复制到内存。挂载保留源 inode 引用，阻止其
文件系统卸载；同一源 inode 的重复挂载（包括别名）返回 EBUSY。可挂载另一个 ISO 中
的 ISO 文件；先卸载内层，再卸载外层。源文件挂载期间不得修改；大小或身份改变、
读取失败会使该挂载停止 I/O，保留上下文直到重启，不提供一致性快照。

文件仍有外部引用时卸载返回忙碌。目录先在私有树中完整解析，再短暂持有 VFS
锁发布；解析、分配、释放和设备读取均在自旋锁之外。读失败或操作所有者异常
终止时保留不能安全回收的上下文，拒绝继续使用，直到重启。

## 实现上限与验证

最多同时保留 16 个挂载上下文；描述符序列最多扫描 256 项；每个目录最多
64 MiB、65536 个逻辑目录项；
每个文件最多 1024 个区段；UTF-8 名称最多 255 字节。超过上限明确返回错误。
每个目录记录的 SUSP 扩展最多处理 64 KiB、4096 个记录和 32 个 CE 连续区；
符号链接目标最多 4095 字节；连续区循环和越界会被拒绝。
文件区段按需从盘面读取，无须在每个 VFS 节点中分配最大区段数组。

公共主机测试：

```sh
python3 -m unittest discover -s OpenXJ380/tests -p test_iso9660.py -v
python3 OpenXJ380/tools/check_iso9660_sources.py
```

在独立 OpenXJ380 仓库中，去掉上述 `OpenXJ380/` 前缀。测试使用 ASan/UBSan，
覆盖真实 xorriso 生成的 Level 1–3/Joliet/Rock Ridge 镜像、大目录、损坏记录、非连续区段
和超过 4 GiB 的稀疏文件。QEMU 集成测试使用独立测试内核与启动盘副本；
生产镜像、测试 ISO 均不由探针修改。父工程的运行命令为：

```sh
python3 tests/run_iso9660_qemu.py --boot-image /path/to/XJ380.img
```

运行器默认分别验证 AHCI 光驱、q35 上的 PIIX IDE 光驱，并在正常用户进程入口运行
独立验收 ELF。内核探针覆盖只读操作拒绝、重复区间挂载、损坏镜像回收、重挂载，以及
四个线程在两个挂载点并发读取时的内容和卸载生命周期。用户态验收覆盖本地 ISO 文件、
中文长名、硬链接、链接跟随/循环、重定位目录、只读操作、重复源文件、内嵌 ISO 的
源引用、mountiso 命令及 Visitor 拒绝。主机侧核对光盘与本地 ISO 文件的内容哈希。
运行器要求启动盘采用 ext4 根分区，以便在副本中注入验收程序和本地 ISO。

通过 e2fsck；IDE/AHCI 各 57 项内核运行时检查和 66 项用户态检查通过。主机解析与来源
清单测试、VFS/块设备/任务退出回归、挂载信息、镜像暂存及构建图测试均通过。
