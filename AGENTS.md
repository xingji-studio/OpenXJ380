## OVERVIEW
XJ380 is a freestanding x86_64 OS: UEFI bootloader, monolithic core kernel, XAPI user-mode API with one CLI example, loadable `.sys` kernel modules, and a staged FAT disk image. `tools/gen_ninja.py` is the canonical build graph generator; no package manager owns the build.

## STRUCTURE
```
XJ380/
├── boot/                 # UEFI BOOTX64.efi, boot menu, EFI protocol handoff
├── kernel/               # KernelMain and core kernel subsystems
├── driver/               # Built-in drivers linked into kernel.krl
├── font/                # Console font (hankaku.bin); built into the kernel
├── include/              # Shared kernel/module ABI headers
├── lib/                  # Small built-in support code
├── kmod/                 # Loadable kernel modules -> out/*.sys -> image /mod
├── user/                 # XAPI runtime/API plus one CLI example
├── third_party/          # Vendored upstream source drops; avoid local edits
├── Bf/                   # Host-independent staging resources
├── tools/                # Image/rootfs/toolchain staging scripts
└── resources/            # Files copied into /system/resources
```

## CODE MAP
| Symbol / target | Type | Location | Role |
|-----------------|------|----------|------|
| `efi_main` | UEFI entry | `boot/bootx64.c` | Initializes EFI protocols, memory map, GOP, boot flags. |
| `KernelMain` | Kernel entry | `kernel/main.cpp` | Brings up CPU, memory, devices, VFS, SMP, syscalls, modules. |
| `ENTRY(KernelMain)` | Linker rule | `linker.ld` | Kernel ELF start symbol and high-half layout. |
| `_start` | User entry | `user/xapi/arch/x86_64/crt0.S` | Jumps to `xapi_start`. |
| `xapi_start` | User runtime entry | `user/xapi/constart.cpp` | Dispatches the CLI example to `main`. |
| `dlmain` | Module entry | `kmod/*/*.cpp` | Entry symbol for shared `.sys` modules. |
| `ninja all` | Integration build | `build.ninja` | Builds boot/kernel, XAPI, the CLI example, and kmods. |
| `ninja vdisk` | Image build | `tools/ninja_build.py` | Creates `XJ380.img` and copies artifacts/resources. |

## CONVENTIONS
- C/C++/ASM are freestanding: `-nostdlib`, `-ffreestanding`, `-fno-builtin`, `-fno-stack-protector`, `-mno-red-zone`; kernel C++ also uses `-fno-rtti`, `-fno-exceptions`.
- Root kernel C is C11; root kernel C++ is GNU++17. User/xapi defaults are C++11-ish; browser hosted code is C++17/C11.
- `.asm` uses NASM. `.S` uses clang. Kernel image links with `ld -T linker.ld --static`.
- Use root `.clang-format` for first-party code: 4 spaces, 120 columns, pointer alignment right, preserve include blocks.
- XINGJI C/C++ style intent: normal code-block braces on their own lines except data/formatter-allowed short blocks; blank line between function implementations; wrap overlong parameter/expression/macro lines.
- Use American English or standard industry terms for function/variable names; core or complex code must include useful comments.
- Keep `*` with the variable name for pointers (`int *p`); put spaces after declaration commas and around assignment `=`.
- Adjacent non-function declarations/assignments should align names or `=` where the existing style does so.
- New first-party headers should start with `#pragma once`.
- `.clangd` files are generated from `.clangd_template` with `ninja gen.clangd`; boot has its own template.
- Treat `third_party/**` and `kmod/netserver/lwip/**` as external unless deliberately syncing/updating integration.
- Keep mandatory core-kernel code in `kernel/`; built-in drivers in `driver/`; loadable modules in `kmod/`.
- User app link rules depend on the generated Ninja XAPI runtime objects under `out/xapi/`.

## ANTI-PATTERNS (THIS PROJECT)
- Do not push directly to `main`; create a separate branch, open a PR, and merge only after review.
- Do not edit generated Mbed TLS files marked `DO NOT EDIT`; regenerate or update wrappers instead.
- Do not use stb font parsing on untrusted fonts; `font/ttf/stb_ttf.h` explicitly has no security guarantee.
- Do not enable unsupported lwIP PPP flags (`CBCP_SUPPORT`, `ECP_SUPPORT`, `DEMAND_SUPPORT`) in this tree.
- Do not call lwIP PPP internals (`pppos_*`, `pppoe_*`) from user code.
- Do not assume root CI boots the OS; CI builds only.
- Do not clean up broad low-level interfaces while fixing bugs; many layouts are ABI contracts.

## BUILD / RUN NOTES
- Defaults: `DEBUG=1`, `SMP=4`, `SUDO=1`, `KVM=1`.
- `DEBUG=1` adds QEMU `-s -S`; `KVM=0` uses `-cpu max`; `SUDO=0` disables the QEMU sudo wrapper.
- `DISPLAY_BACKEND` is the QEMU display backend (`gtk` by default), not X11 `$DISPLAY`.
- `ninja all` downloads `liballoc-x86_64.a` if missing.
- `ninja vdisk` may need privileged `sgdisk`, `mkfs.vfat`, and `mcopy`; temporary root defaults under `/tmp/xj380-vdisk-$(id -u)/XJ380`.
- Main artifacts: `out/`, `XJ380.img`, optional `XJ380.vmdk`, `serial.log`, generated `.clangd`, generated `kernel/build_config.h`.
- Version strings live in both `tools/stage_image_base.sh` and `kernel/build_settings.h`.
- `tools/check_line_endings.sh` rejects CRLF in `tools/*.sh`.
